# 인천 계양테니스장 예약 정책 조사

## 최신 점검 결과

후속 사용자 실행에서 `init-gyeyang`의 `registered=true`를 확인했다. 이어서
`collection-plan`은 대상 2곳·브라우저 필요를 보고했고, `watch-slots`는
수집 2회·관측 99개·오류 0개·알림 성공 0개·실패 0개를 보고했다.
이는 사용자 로컬 DB 등록과 수동 수집 성공의 근거다. 실제 예약 가능 슬롯 발견이나
계양의 Telegram 알림 발송 성공, GitHub 예약 실행 성공으로 확대 해석하지 않는다.

2026-10-26 사용자가 제공한 `probe-gyeyang --date 2026-10-28` 결과에서
`ok=true`, `registered=false`, `court_count=6` 및 96개 시간대 관측을 확인했다.
관측 시각은 한국 시간 21:19:55~21:20:20이다. 아래 매핑은 이 사용자 실행 결과에

Telegram 알림 수신은 아직 미검증이다.

첫 조회 결과만으로 시설 DB 등록·구독 생성·GitHub 코드 반영·정기 실행이
증명되지는 않는다. 후속 등록·수동 실행 결과는 위에 별도로 기록했다.
아래 내용은 단계별 조사·개발 당시의 기록이며 최신 성공 범위는
이 절을 기준으로 판단한다.

조사일: 2026-10-26 (Asia/Seoul). 강서구 시설과 별개인 인천 계양구 시설이다.
웹 검색 도구의 공식 페이지 열람 결과를 정리했다. 도구가 제공한 예약 페이지는 2주 전,
시설 안내는 1주 전, 공지사항 본문은 6일 전 수집본으로 표시됐다.
따라서 조사일의 실시간 화면을 직접 검증한 기록과 구분한다.

## 공식 안내에서 확인한 공통 규칙

- 한국 시간 매주 화요일 14:00에 예약을 연다.
- 대상 이용일은 해당 주 수요일부터 다음 주 화요일까지 7일이다.
- 홈페이지 회원가입이 필요하며 선착순으로 접수한다.
- 계정당 하루 1회, 최대 2시간이며 7일간 최대 2회 예약할 수 있다.
- 당일 이용은 시작 1시간 전까지 사전 예약해야 한다.
- 동반자가 계정을 나누어 같은 날 연속 시간을 확보하는 방식은 제한된다.
- 수업 및 사전 허가 클럽의 전용 코트는 일반 예약에서 제외된다.
- 주민 우선 접수와 일반 접수를 나눈 오픈 시각은 확인한 안내에 기재되어 있지 않다.
  이를 주민 우선제 없음으로 단정하지 않는다.

운영시간은 06:00~22:00이다. 1월 1일, 설·추석 연휴와
3·6·9·12월 마지막 주 금요일은 휴무 안내가 있다.
휴무나 전용 코트 배정 때문에 개별 시간대 예약이 제한될 수 있으며,
공통 운영시간을 모든 코트의 실제 예약 가능 시간으로 사용하지 않는다.

## 일정 계산 예시와 기존 시스템 적용

안내 규칙을 그대로 계산하면 2026-10-27 화요일 14:00에
2026-10-28 수요일~2026-11-03 화요일 이용분이 열린다.
이는 규칙에 따른 계산 예시이며 실제 예약 화면의 오픈 보장이 아니다.

기존 `ReservationPolicy.open_days_before` 방식은 이용일마다 일정한 선행 일수를
빼므로 이 주간 일괄 오픈 규칙을 표현할 수 없다. 이용일에 따라 오픈과의 간격이
1~7일로 달라진다. 단순히 7일 전 정책으로 등록하면 잘못된 알림이 된다.

프로젝트에는 주간 일괄 오픈 유형, 한국 시간 기준 요일·시각, 대상 주간 범위,
정책 출처 점검 이력과 검증 보류 기능을 추가했다. 휴무 예외 및 전용 코트별 제한은
자동 수집하지 않으며, 공통 정책 알림에 실제 예약 가능 보장을 포함하지 않는다.
새 DB에는 `alembic upgrade head` 적용 후 `init-gyeyang-opening`으로 공식 정책을
최초 확인해야 한다. 코드 변경만으로 이미 운영 중인 DB와 Worker에 반영되지는 않는다.

## 남은 검증

1. 브라우저 연결 복구 후 실내·실외 선택 목록의 6면 이름과 외부 식별자를 확인한다.
2. 각 코트 화면에서 공통 안내 적용 및 수업·클럽 전용 배정을 구분한다.
3. 주민 구분과 임시 휴장·대회 등 최근 예외 공지를 확인한다.
4. 정기 수집 전 robots.txt 및 이용약관의 허용 범위를 확인한다.
   이번 로컬 접근은 DNS 해석 실패, 웹 도구의 robots 열람은 접근 실패였다.
   예약 자동화나 반복적인 수집은 실행하지 않았다.

현재 상태는 **시설 공통 정책 조사 완료 / 코트별 전수 확인 미완료 / 주간 정책 확인·일정 계산·Telegram 알림 경로 구현**이다. 실제 운영 완료는 DB 마이그레이션, 최초 정책 확인, 활성 구독, GitHub Actions 및 Telegram 발송 기록을 확인한 뒤에만 판단한다.

## 잔여석 어댑터 구현 (2026-10-26)

`src/tenniswatch/collectors/gyeyang.py`에 HTTPX/BeautifulSoup 어댑터를 추가했다.
기존 상태 전이·이벤트 중복 방지·발송 재시도·소유자별 구독 필터를 재사용한다.
기존 기본 레지스트리에 등록했지만 실제 시설은 자동으로 DB에 추가하지 않는다.

**모의 계약 테스트 통과와 실제 사이트 연동 성공은 다르다.** 현재 DNS 해석 실패와
브라우저 시간 초과 때문에 실제 HTML 구조·전체 코트 식별자·예약 가능 라벨은 미검증이다.
테스트의 코트 이름·식별자는 합성 자료다. 특히 `예약가능`은 어댑터가 허용하는
명시적 상태 라벨이며, 실제 사이트에서 관측했다고 주장하지 않는다.

사이트가 `select[name=rca_id]`, `rca_id2`, `rs_idx`와 월간 달력 표를 제공하는 경우에만
처리한다. 월별 이동 링크의 `year`, `month` 매개변수 형식은 공식 페이지 링크에서 확인했다.
번호를 순회하거나 예약 버튼을 클릭하지 않고 실제 선택 목록에 있는 값만 조회한다.
카테고리가 두 개로 분리되어 있으면 해당 카테고리도 확인한다.
실내·실외 각각 3면, 날짜별 06~21시 시작의 16개 한 시간 슬롯이 모두 있어야 성공한다.
휴무일에 슬롯 행이 생략되면 마감으로 추정하지 않고 `INCOMPLETE_SNAPSHOT`으로 중단한다.
실제 사이트의 다른 구조나 상태명이 발견되면 파서를 확인 후 수정해야 한다.

상태 처리:

- `예약가능`: 명시적 예약 가능. 취소선/비활성 표기가 함께 있으면 오류.
- `예약완료`, `예약마감`, `예약불가`: 예약 불가.
- `예약예정`: 아직 오픈 전이며 잔여석 알림 대상에서 제외.
- 누락·알 수 없는 상태: 날짜 수집 실패, 기존 DB 상태 및 확인 시각 보존.

기존 DB의 예약 상태는 이진 가용 상태이므로 위 예약 불가 사유를 따로 저장하지 않는다.
`available=false`를 모두 예약 완료로 설명해서는 안 된다.
월간 응답은 한 작업 안에서 코트별로 재사용하며 실제 응답 확인 시각을 유지한다.
예약자 이름이나 원본 HTML은 저장·출력하지 않는다. robots 확인 실패·접근 제한·리디렉션은
중단하며 요청 간격은 최소 5초 및 robots 설정 중 더 긴 값을 따른다.

### 실제 연동 확인 순서

먼저 DB 변경이나 Telegram 발송 없이 조회한다. 날짜는 확인하려는 이용일로 바꾼다.

```sh
.venv/bin/tenniswatch probe-gyeyang --date 2026-10-28
```

성공하면 `ok=true`, `court_count=6`, 슬롯별 코트·시작/종료 시각·가용 상태·확인 시각·예약 URL이
나온다. 실패하면 원본 예외 대신 `error_code`만 출력하고 종료 코드 1로 끝난다.
`ROBOTS_UNAVAILABLE`은 접근 규칙을 확인하지 못한 상태이며 우회하지 않는다.
`COURT_INVENTORY_UNVERIFIED` 또는 `PAGE_LAYOUT_CHANGED`는 실제 선택 목록/구조 확인이 필요하다.

6면의 날짜 전체 수집이 성공한 경우에만 다음 명령으로 시설·실제 코트 목록을 등록한다.
이 명령도 등록 전 동일한 실시간 검증을 수행하며 정책이나 구독은 생성하지 않는다.
관측값을 저장하거나 알림을 발송하지 않고 기존 감시 작업의 첫 수집을 기다린다.
DB 트랜잭션 실패 시 등록 성공으로 출력하지 않는다.

```sh
.venv/bin/tenniswatch init-gyeyang --date 2026-10-28
```

등록 이후 Telegram에서 예를 들어 “10월 28일 계양테니스장 18시 이후 빈자리 감시해 줘”라고
요청한다. 등록된 조건은 `collection-plan`, 수집·알림은 `watch-slots`로 확인한다.
날짜가 기존 기본 7일 수집 범위 안에 있는지 확인한다. 실제 주기 실행에는 새 코드를
GitHub 저장소에 반영해야 한다. 수집 성공과 운영 배포를 확인하기 전 자동 감시 중이라고
안내하지 않는다. Worker의 기존 시설 검색과 구독 도구를 사용하며 별도 LLM 호출을 추가하지 않는다.

예약 오픈 알림을 시작하려면 마이그레이션 후 아래 명령으로 공식 정책을 동기화하고 일정을 계산한다. 최초 확인 시 공식 페이지가 알려진 규칙과 다르면 자동 승인하지 않는다.

```sh
.venv/bin/alembic upgrade head
.venv/bin/tenniswatch init-gyeyang-opening
.venv/bin/tenniswatch opening-status
```

Telegram에서 이용 날짜 또는 요일, `예약 오픈 알림`을 요청한다. 기본 알림 시점은 전날·1시간 전·오픈 후 첫 정기 확인이며, 사용자가 한 시점만 요청할 수 있다. GitHub Actions의 예약 실행은 지연될 수 있어 시각 보장을 하지 않는다. 현행 지원 범위는 계양의 검증된 공통 일반 정책이며 주민 우선 정책과 코트별 휴무/전용 배정은 확정하지 않는다.

### 선택값 검증 오류 점검

사용자 실행에서 `PAGE_SELECTION_MISMATCH`가 보고됐다. HTTP 응답의 선택값 검증 단계에
도달했으며 코트별 수집 성공을 의미하지 않는다. 단일 드롭다운에 `selected` 속성이
없을 때 브라우저의 첫 활성 항목 선택 규칙을 반영하도록 수정했다. 이것이 실제 오류의
원인인지는 아직 미확인이다. 요청한 코트 번호를 선택값으로 대신 사용하는 우회는 하지 않는다.
재실행 시 오류가 유지되면 `selection_diagnostics`의 필드별 요청 숫자값·선택 숫자값·옵션
개수로 불일치 지점을 확인한다. 옵션 이름·페이지 본문·스크립트·원본 예외는 출력하지 않는다.

### 동적 선택 목록 대응

사용자 진단에서 `rca_id=10`은 선택됐지만 `rca_id2` 옵션은 0개, `rs_idx`는 빈 기본
옵션만 있는 초기 응답을 확인했다. HTTP HTML의 선택값만으로는 확인할 수 없으므로
빈 동적 목록을 감지한 경우 Playwright로 한 번 전환하고 이후 같은 브라우저를 재사용한다.

```sh
.venv/bin/python -m playwright install chromium
.venv/bin/tenniswatch probe-gyeyang --date 2026-10-28
```

실제 DOM의 선택값이 요청한 분류·코트와 일치할 때까지 최대 25초 기다린다.
JS로 갱신된 선택값은 HTML의 `selected` 속성과 다를 수 있어 DOM의 `value`를 읽어 검증한다.
요청값을 실제 선택값으로 대체하지 않는다. 로딩 실패는 `PAGE_SELECTION_TIMEOUT`,
브라우저 시작 실패는 `BROWSER_UNAVAILABLE`로 구분한다. 로그인·예약·CAPTCHA는 조작하지 않는다.
robots 검사와 탐색 간격은 브라우저 경로에도 동일하게 적용한다. 정기 작업의 기존
`needs_browser` 설정으로 Chromium이 설치되며 별도 워크플로 변경은 필요 없다.
실제 코트 6면의 시간표 수집 성공 여부는 여전히 추가 실행으로 확인해야 한다.

후속 사용자 실행에서 진단 정보 없는 `PAGE_SELECTION_MISMATCH`가 보고됐다.
브라우저 경로의 DOM 선택값 반영 단계에도 안전한 진단을 추가했고, HTML과 선택값을
하나의 JavaScript 실행으로 읽어 AJAX 갱신 사이의 시간차를 줄였다.
오류 시 `stage`, `live_numeric_value`, `live_value_match_count`로 실제 DOM 값과
HTML 옵션의 불일치·중복을 구분한다. 실제 원인은 이 진단 결과로 추가 확인해야 하며,
오류가 해결됐거나 실수집에 성공했다고 간주하지 않는다.

사용자 재실행에서 `COLLECTION_FAILED`가 보고되어 예기치 않은 예외에도 안전한
`failure_details`를 추가했다. 예외 종류는 허용 목록의 이름만, 코드 위치는 프로젝트의
파일명과 줄 번호만 출력한다. 메시지·인자·로컬 변수·전체 경로·원본 traceback은 출력하지 않는다.
브라우저 처리 중 예상치 못한 오류는 `BROWSER_PROCESSING_FAILED`와 실패 단계로 구분한다.
이는 진단 개선이며 실제 사이트 오류가 해결됐다는 의미가 아니다.

후속 진단은 `snapshot` 단계의 Playwright `Error`였다. 정확한 브라우저 예외 사유는
아직 확인되지 않았으므로 페이지의 전역 함수 변경이나 CSP 문제로 단정하지 않는다.
직접 `page.evaluate`로 Object.fromEntries를 실행하던 방식을 제거하고 Playwright의
`input_value` 및 `content` API로 읽는다. 읽기 전후 선택값이 다르면
`PAGE_SELECTION_CHANGED`로 중단한다. 같은 선택값과 HTML 옵션의 일치 검증은 유지한다.
기존의 단일 JavaScript 스냅샷 방식은 이 변경으로 대체됐다.

후속 사용자 진단은 코트 번호 없는 `rca_id2=1020` 요청의 선택 목록이 비어 있는 상태였다.
동적 브라우저 경로의 분류 발견은 이 불완전한 URL로 이동하는 대신 알려진 첫 공개 링크를
정상 로딩한 뒤 `rca_id2` 드롭다운을 변경하도록 수정했다. 이전 분류의 코트 목록과 다른
숫자 선택 목록이 나타날 때까지 기다리고, 자동 선택값이 없으면 새 목록의 첫 실제 값을
선택한다. 임의 코트 번호를 URL에 넣지 않는다. 코트 목록이 바뀌지 않으면
`CATEGORY_OPTIONS_TIMEOUT`으로 중단한다. 이 UI 동작은 공개 분류 탐색이며 예약 버튼을
누르지 않는다. 해당 수정의 실제 사이트 성공 여부는 아직 미검증이다.
