# 내 알림 대시보드

기존 감시 조건, 매일 결과 보고 시각, 최근 수집 기록과 Telegram 알림 기록을 조회하는 화면입니다. 조회 전용이며 설정 변경은 Telegram에서 진행합니다. 첫 구현은 기존 Cloudflare Worker의 `/dashboard`와 `/api/dashboard`를 사용하고 새 DB 마이그레이션이나 비밀키 추가는 필요하지 않습니다. `0008` 스키마가 적용되어 있어야 합니다.

## 사용 순서

```bash
cd /Users/kkh/TennisWatch/apps/telegram-worker
npx wrangler deploy
```

1. 배포 후 본인 봇에 `/dashboard`를 보냅니다. 다음 inbox 처리 시각까지 1분 이상 걸릴 수 있습니다.
2. 봇이 알려준 `https://tenniswatch-telegram-worker.tenniswatch-kkh.workers.dev/dashboard`를 엽니다.
3. 같은 답변에 있는 접속 코드를 화면에 붙여넣습니다. 코드는 15분 동안 본인 설정을 읽을 수 있는 자격 증명이므로 공유하거나 로그·스크린샷에 포함하지 않습니다.
4. 활성/전체 조건 필터와 새로고침을 사용할 수 있습니다. 연결 해제 또는 코드 만료 시 다시 발급받습니다.

`/dashboard` 명령은 LLM을 호출하지 않아 AI 일일 예산과 무관합니다. 일반적인 Telegram 접수·DB 저장·정기 inbox 처리 경로는 사용합니다.

## 표시 범위

- 감시 조건: 시설, 지역, 이용 날짜/반복 요일, 시간대, 알림 종류와 상태. 최대 100개 새 감시 조건 및 100개 기존 구독.
- 매일 결과 보고: 활성 여부, 한국 시각, 다음 기준 시각. 실제 예약 실행은 지연될 수 있습니다.
- 수집 기록: 해당 사용자의 관심 시설에서 최근 15건. 관측 수, 성공/일부 실패/실패, 확인 시각.
- 알림 기록: 해당 사용자의 최근 15건. Telegram API 전송 완료와 사용자 단말 수신은 구분합니다.
- 특정 날짜 조건은 날짜가 지나면 기간 종료로 표시합니다. 감시 조건 상태가 ACTIVE여도 배포·수집·현재 잔여석 성공을 보장하지 않습니다.

예약 가능한 코트의 실시간 조회나 설정 수정 화면은 이번 범위에 포함하지 않습니다. 화면은 모의 운영 데이터를 실제 결과처럼 채우지 않습니다. 조회 실패 시 실패 안내를 표시하고 새로고침 실패로 남은 이전 화면은 그 사실을 안내합니다.

## 인증과 데이터 격리

접속 코드는 검증된 개인 Telegram 요청에서만 발급합니다. 기존 웹훅 Secret으로 목적을 분리한 HMAC-SHA256 서명을 생성하며, 사용자·채팅·읽기 전용 범위·발급 및 만료 시각을 검증합니다. 코드는 15분 동안 재사용 가능한 bearer 자격 증명입니다. 일회용 로그인 코드라고 안내하지 않습니다.

- 허용 채팅 목록 및 활성 사용자 여부를 API에서 다시 확인합니다.
- 사용자 ID를 URL이나 모델 인자로 받지 않습니다. 서명으로 인증한 식별자를 기준으로 소유자를 조회합니다.
- 사용자별 감시·구독·일일 설정·알림 쿼리에 소유자 필터를 적용합니다. 수집 이력은 해당 감시 시설로 제한합니다.
- DB 서비스 키는 서버에서만 사용하며 HTML·API 응답에 포함하지 않습니다. 원문 DB 오류는 응답하지 않습니다.
- 공개 `/dashboard`에는 로그인 화면만 있습니다. 개인 데이터 API에는 인증이 필요합니다. 상태 변경 요청은 거절합니다.
- 데이터 응답은 `no-store`이며 접속 코드는 URL·localStorage·sessionStorage에 저장하지 않습니다. 만료 시 화면을 비우며 페이지 새로고침도 로그아웃 효과가 있습니다.
- CORS는 같은 Worker 출처와 설정된 대시보드 사이트 출처만 허용합니다. CORS 자체를 인증 수단으로 간주하지 않습니다.
- 접속 코드는 발급 답변의 재전송을 위해 기존 private inbox 응답 캐시에 남을 수 있습니다. 해당 테이블은 RLS로 보호되며 서명 검증의 만료 시각은 재전송해도 연장되지 않습니다. 보존 정책은 운영 문서를 따릅니다.

## 배포·검증 상태

Worker 모의 테스트에는 코드 만료·서명 변조·다른 사용자·비허용 출처·수정 요청 거부·DB 소유자 필터·DB 오류 숨김·AI 없는 봇 코드 발급을 포함합니다. 실제 운영 Worker 배포와 봇에서 코드 발급·화면 조회는 배포 후 검증해야 합니다. 브라우저 연결이 응답하지 않아 시각적 QA는 아직 수행하지 못했습니다.

Sites 스킬로 별도 비공개 프로젝트 `appgprj_6adf34a001e0819195a8e4055f7d22bb`도 생성했습니다. 소스 저장소 DNS 연결 실패로 동기화·게시하지 못했으므로 전용 Sites 주소는 배포 완료로 표시하지 않습니다. UI 소스는 두 경로에서 공유합니다. `.openai/hosting.json`의 ID를 보존하고, 별도 게시를 재개할 때 같은 프로젝트와 새로 발급받은 소스 쓰기 자격 증명을 사용합니다. 기존 Worker 경로는 이 별도 게시와 무관하게 배포할 수 있습니다.
